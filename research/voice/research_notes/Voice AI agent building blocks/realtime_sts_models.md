# Realtime speech-to-speech (STS) and full-duplex voice models — state as of 2026-10-17

All prices and statuses were checked on 2026-10-17 unless a different date is given. "Vendor-reported" means the vendor published the number and I found no independent measurement of it. Model IDs below come from vendor docs. Where an ID appears only in secondary sources, it says so.

## 1. OpenAI: Realtime API (gpt-realtime family) and GPT-Live-1

### Takeaway
OpenAI now runs two voice stacks. The **Realtime API** (`v1/realtime`, current flagship `gpt-realtime-2.1` and `gpt-realtime-2.1-mini`) is a half-duplex STS model: one model handles audio, reasoning and tools, VAD drives turn-taking, and it is billed per token. **GPT-Live-1** (launched in the API on 2026-09-10) is a full-duplex "voice front end" billed at $0.05/min. It hands reasoning and tools to a backend model ("delegation"). OpenAI did not say whether Realtime is being superseded.

### Cited Findings
**Model lineage (dates)**
- GPT-Realtime-2 was announced in May 2026 (2026-05-07 or 05-08; secondary sources disagree) as "our most intelligent voice model yet, bringing GPT-5-class reasoning to voice agents." It shipped with companion models gpt-realtime-translate and gpt-realtime-whisper. — [OpenAI on X](https://x.com/OpenAI/status/2052438194625593804?lang=en); [dsebastien](https://www.dsebastien.net/2026-05-07-gpt-realtime-2-openais-voice-model-gets-gpt-5-class-reasoning/); [Handy AI](https://handyai.substack.com/p/model-drop-gpt-realtime-2) (secondary)
- `gpt-realtime-2.1` and `gpt-realtime-2.1-mini` were announced on the OpenAI Developer Community on 2026-07-06. 2.1 "updates GPT-Realtime-2 with improved alphanumeric recognition, silence and noise handling, and interruption behavior," and adds configurable reasoning effort. Mini is "a faster, lower-cost option." OpenAI says p95 latency fell "by at least 25% across Realtime voice models through improved caching" (vendor-reported). The announcement deprecates nothing. Claims in the thread that `gpt-realtime` is "Deprecated" come from community members, not OpenAI. — [OpenAI Developer Community](https://community.openai.com/t/new-realtime-models-on-the-api-gpt-realtime-2-1-and-gpt-realtime-2-1-mini/1385896)
- Older IDs still listed by Azure: `gpt-realtime-1.5`, `gpt-realtime`, `gpt-realtime-mini`. — [Microsoft Learn, Voice Live](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/voice-live)

**gpt-realtime-2.1 model card (vendor docs)**
- Described as a "Reasoning model with tool use." Context window 128,000 tokens, max output 32,000 tokens, knowledge cutoff 2024-09-30. Reasoning effort is configurable ("higher effort can raise latency and output token usage"). Endpoint is `v1/realtime` only (no Chat Completions, Responses or Batch). Supports function calling and prompt caching. The only snapshot listed is `gpt-realtime-2.1`. The card states no GA/preview status. — [OpenAI model page](https://developers.openai.com/api/docs/models/gpt-realtime-2.1)

**Pricing per 1M tokens (checked 2026-10-17)**
| Model | Text in / cached / out | Audio in / cached / out | Image in / cached |
|---|---|---|---|
| gpt-realtime-2.1 | $4.00 / $0.40 / $24.00 | $32.00 / $0.40 / $64.00 | $5.00 / $0.50 |
| gpt-realtime-2.1-mini | $0.60 / $0.06 / $2.40 | $10.00 / $0.30 / $20.00 | $0.80 / $0.08 |
— [OpenAI model page (2.1)](https://developers.openai.com/api/docs/models/gpt-realtime-2.1); [OpenAI Developer Community (2.1 + mini)](https://community.openai.com/t/new-realtime-models-on-the-api-gpt-realtime-2-1-and-gpt-realtime-2-1-mini/1385896). I did not open the mini model card itself; the mini prices come from OpenAI's forum announcement.
- Token rate for converting to minutes: Azure documents roughly 10 audio tokens/sec on input and 20 tokens/sec on output for Azure OpenAI realtime models. — [Microsoft Learn, Voice Live](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/voice-live)

**Transport, session, voices, turn-taking**
- WebRTC in the browser, WebSocket on the server. The GA interface replaces the beta, and OpenAI says: "If you still have a beta Realtime integration, migrate it to the GA interface"; also remove the `OpenAI-Beta: realtime=v1` header. Tools, MCP servers and connectors are supported. — [OpenAI Realtime guide](https://developers.openai.com/api/docs/guides/realtime)
- SIP: point the SIP trunk at `sip:$PROJECT_ID@sip.api.openai.com;transport=tls` (EU: `sip-eu.api.openai.com`). The webhook `realtime.call.incoming` hands over a `call_id`, and you then POST accept / reject (default 603) / refer (`tel:` or `sip:` target) / hangup. A sideband WebSocket is available at `wss://api.openai.com/v1/realtime?call_id=…`. Signaling runs over TLS on port 5061 and media over SRTP/UDP. — [OpenAI Realtime SIP guide](https://developers.openai.com/api/docs/guides/realtime-sip)
- "The maximum duration of a Realtime session is 60 minutes." — [OpenAI Realtime conversations guide](https://developers.openai.com/api/docs/guides/realtime-conversations)
- Voices: alloy, ash, ballad, coral, echo, sage, shimmer, verse, marin, cedar. OpenAI recommends marin or cedar for best quality. "Once the model has emitted audio in a session, the voice cannot be modified for that session." — [OpenAI Realtime conversations guide](https://developers.openai.com/api/docs/guides/realtime-conversations)
- Turn detection: VAD is on by default, and examples use `semantic_vad`. Setting `turn_detection: null` turns it off. Barge-in: over WebSocket the client stops playback and sends `conversation.item.truncate`; over WebRTC "the server will automatically truncate unplayed audio when there's a user interruption." — [OpenAI Realtime conversations guide](https://developers.openai.com/api/docs/guides/realtime-conversations)

**GPT-Live-1 (full-duplex, delegation architecture)**
- Announced 2026-09-10. It "listens and speaks simultaneously" and delegates deeper reasoning to a backend model, tools or agent framework. Transports: WebRTC (recommended "in browser, mobile, and server applications"), WebSockets, and telephony/SIP. Pricing: "$0.05 per minute, billed per second," with backend model and tool usage billed separately. Twelve voices: Quartz, Ripple, Vesper, Willow, Stone, Gleam, Meridian, Bossa, Tempo, Beacon, Delta, Cinder. — [OpenAI Developer Community announcement](https://community.openai.com/t/introducing-gpt-live-1-in-the-api/1396471)
- Delegation modes: "Responses delegation" (OpenAI runs the backend model; "your application still runs your own function tools") or "client delegation" (bring your own model or agent harness). "Backend work can continue when the caller interrupts the assistant," and the app decides whether to finish or cancel it. The guide links to a migration guide from Realtime to GPT-Live. — [OpenAI GPT-Live guide](https://developers.openai.com/api/docs/guides/live)
- The SIP guide describes a newer `/v1/live/sessions` API with model `gpt-live-1` in examples. On that path, outbound calls must be enabled per organization, "ringing is limited to 3 minutes, and a connected call is limited to 2 hours," and request bodies are capped at 1 MiB. The older `live.call.incoming` webhook is deprecated. — [OpenAI Realtime SIP guide](https://developers.openai.com/api/docs/guides/realtime-sip)
- Vendor-reported benchmarks, with GPT-Live-1 paired with GPT-6 Astra at medium reasoning: Tau3 first-attempt completion 83.6% vs 45.7% for GPT-Realtime-2.1; TauBanking 38.1%; turn-taking latency 0.798 s vs 1.41 s for GPT-Realtime-2.1; Full Duplex Bench v1.5 interactivity 80.1%. — [OpenAI Developer Community announcement](https://community.openai.com/t/introducing-gpt-live-1-in-the-api/1396471)
- Transcripts are disputed. OpenAI says ASR transcripts are provided, but a forum user reported "GPT-Live doesn't transcribe the user's voice," and the thread leaves this unresolved. — [OpenAI Developer Community announcement](https://community.openai.com/t/introducing-gpt-live-1-in-the-api/1396471)

**Independent measurement**
- Artificial Analysis (no per-model measurement date shown): GPT-Realtime-2 (High) scores 97% on Big Bench Audio with 1.14 s time-to-first-audio, at $1.15/hr audio input and $4.61/hr audio output. — [Artificial Analysis S2S leaderboard](https://artificialanalysis.ai/speech-to-speech)

### Inferences
- At about 10 input and 20 output tokens/sec, gpt-realtime-2.1 costs about $0.019 per minute of user audio and about $0.077 per minute of model audio before context re-reads. Mini costs about $0.006 and $0.024 per minute. These are my arithmetic from the documented prices and Azure's token rate, not a vendor figure.
- GPT-Live-1's $0.05/min covers only the voice layer, so total cost = $0.05/min + backend LLM tokens + tools. For a tool-heavy agent it can cost more or less than Realtime depending on the backend model chosen.
- GPT-Live is OpenAI's own move toward a "voice front end + text backend" hybrid. Its large vendor-reported Tau3 gain over GPT-Realtime-2.1 (83.6% vs 45.7%) suggests OpenAI itself sees single-model STS tool reliability as the weak point.

### Gaps
- **Hungarian:** none of the OpenAI Realtime or GPT-Live pages I fetched lists supported languages. Hungarian support is undocumented, not confirmed.
- GA/preview status of gpt-realtime-2.1 and GPT-Live-1 is not stated on the pages I fetched.
- GPT-Live session maximum (beyond 2-hour SIP outbound calls) and its voice/language list in the docs (as opposed to the forum post) are unconfirmed.
- I did not open the gpt-realtime-2.1-mini model card (context window and max output unconfirmed).

## 2. Google: Gemini Live API (native audio)

### Takeaway
Google's current Live models are **`gemini-3.8-live`** (labeled "New Stable"; the default low-latency voice agent) and **`gemini-3.8-live-extended-thinking`** (stable; more reasoning, async tools only). `gemini-3.1-flash-live-preview` is now legacy. It is the cheapest major hosted STS, published per minute: about $0.005/min audio in and $0.018/min audio out. Google officially documents Hungarian (`hu`), and its sessions have the hardest limits of the hosted options (15 min audio-only without compression, connections around 10 min).

### Cited Findings
- Model list on the vendor docs: `gemini-3.8-live` ("New Stable", "the default option for most low-latency voice agent experiences and real-time dialogue without reasoning delays"); `gemini-3.8-live-extended-thinking` ("New Stable"); `gemini-3.5-live-translate-preview` (preview, STS translation, 70+ languages); `gemini-3.5-transcribe-live` (STT); `gemini-3.1-flash-live-preview` ("Legacy… We recommend updating to Gemini 3.8 Live"); `gemini-2.5-flash-native-audio-preview-12-2025` (access-limited, "not deprecated", served "until further notice"). — [Gemini models page](https://ai.google.dev/gemini-api/docs/models)
- `gemini-3.8-live`: input limit 131,072 tokens, output 65,536. Accepts text/image/audio/video and returns text/audio. Page last updated September 2026. Migrating from 3.1 Flash Live means changing the model string and dropping `thinking_level`. NON_BLOCKING async function calling is now the default. — [Gemini 3.8 Live model page (via search snippet)](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-live?hl=ko). The release date 2026-09-15 comes from a third-party catalog only ([datalearner](https://www.datalearner.com/ai-models/pretrained-models/gemini-3-8-live)) and is unconfirmed.
- Transport: "Stateful WebSocket connection (WSS)." WebRTC is available only via partner integrations. Audio in: 16-bit PCM at 16 kHz. Audio out: 24 kHz. Supports JPEG frames at up to 1 FPS, barge-in ("users can interrupt the model at any time"), function calling and Google Search, proactive audio, affective dialog, and input/output transcriptions. — [Gemini Live API overview](https://ai.google.dev/gemini-api/docs/live)
- Languages: the Live API "supports the following 99 languages," and **Hungarian is listed as `hu`**. (The overview page says "70 supported languages," which conflicts with the capability guide's 99.) — [Gemini Live guide](https://ai.google.dev/gemini-api/docs/live-guide); conflicting count in [Gemini Live overview](https://ai.google.dev/gemini-api/docs/live)
- Feature matrix: affective dialog and proactive audio are "not supported in Gemini 3.1 Flash Live." Affective dialog needs `v1beta` and `enable_affective_dialog: true`. Thinking on 3.8 Live is "Supported (interleaved reasoning)" with `thinkingLevel` omitted. Extended Thinking takes low/medium/high. Function calling: 3.8 Live supports NON_BLOCKING (default) plus BLOCKING, with SILENT / WHEN_IDLE / INTERRUPTED scheduling. Extended Thinking is NON_BLOCKING only. 3.1 Flash Live is "sequential only." Context: "128k tokens for native audio output models," "32k tokens for other Live API models." Voices are the TTS voice catalog (count not stated). — [Gemini Live guide](https://ai.google.dev/gemini-api/docs/live-guide)
- VAD/barge-in: on interruption "the ongoing generation is canceled and discarded." Automatic VAD is set via `realtimeInputConfig.automaticActivityDetection`, or you can send `activityStart`/`activityEnd` manually. Recommended `silenceDurationMs` is 500–800 ms, and the server default is about 800 ms. — [Gemini Live guide](https://ai.google.dev/gemini-api/docs/live-guide)
- Session limits: "Without compression, audio-only sessions are limited to 15 minutes, and audio-video sessions are limited to 2 minutes." Connection lifetime is "around 10 minutes." `contextWindowCompression` (sliding window) can make sessions last indefinitely. Resumption tokens are "valid for 2 hr after the last sessions termination." The server sends `GoAway` with `timeLeft` before disconnecting. — [Gemini Live session management](https://ai.google.dev/gemini-api/docs/live-session)
- Pricing (paid Standard tier, per 1M tokens, checked 2026-10-17). The table is shared by gemini-3.8-live, 3.8-live-extended-thinking and 3.1-flash-live-preview: text in $0.75; **audio in $3.00 or $0.005/min**; image/video in $1.00 or $0.002/min; text out (incl. thinking) $4.50; **audio out (incl. thinking) $12.00 or $0.018/min**. A free tier exists, and free-tier data "may be used to improve Google's products." Search grounding: 5,000 free requests/month, then $14 per 1,000. `gemini-2.5-flash-native-audio-preview-12-2025`: text in $0.50, audio/video in $3.00, text out $2.00, audio out $12.00. — [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing)
- Independent measurement (Artificial Analysis): Gemini 3.8 Live Extended Thinking (High) scores 98% Big Bench Audio with 1.35 s TTFA. Gemini 3.1 Flash Live High scores 97% with 2.99 s TTFA at $0.35/hr input and $1.38/hr output. The plain `gemini-3.8-live` was not in the extracted top rows. — [Artificial Analysis](https://artificialanalysis.ai/speech-to-speech)

### Inferences
- Thinking tokens are billed at the audio/text output rate ("incl. thinking"), so Extended Thinking can cost noticeably more per conversational minute than its headline per-minute price suggests.
- The roughly 10-minute connection cap means any production Gemini Live agent needs reconnect + resumption-token handling and GoAway handling from day one. This is a real engineering cost that OpenAI's 60-minute session does not impose.

### Gaps
- No vendor latency number for 3.8 Live was found. Vertex AI (enterprise) pricing, SLAs and regional data residency for 3.8 Live were not checked.
- Whether affective dialog and proactive audio are supported on the 3.8 models is implied but not stated explicitly.

## 3. xAI: Grok Voice realtime API

### Takeaway
xAI has an official realtime STS endpoint (`wss://api.x.ai/v1/realtime`, alias `grok-voice-latest`). The current model is **grok-voice-3.0**, and grok-voice-2.0 is deprecated. It is priced at a flat **$0.08/min**. Independently it is the fastest major hosted STS (0.81 s TTFA) with a top-tier reasoning score, but its docs are thin on tools, session limits and status.

### Cited Findings
- Endpoint `wss://api.x.ai/v1/realtime?model=grok-voice-latest`. Separate REST TTS (`/v1/tts`) and STT (`/v1/stt`, default `grok-voice-transcribe-2.0`, "38+ languages"). WebSocket transport is documented, while WebRTC and Twilio appear only as linked demos. Ephemeral tokens are available for client-side use. Default voice is `eve`. Custom voice cloning from a reference clip ("max 120s") works in realtime. Server VAD (`turn_detection: {type: "server_vad"}`). Tools are configured in the session, with the example showing built-in `{"type": "web_search"}`. Claims SOC 2 Type II, HIPAA eligibility and GDPR, plus "sub-second latency" (vendor-reported). — [xAI voice guide](https://docs.x.ai/docs/guides/voice)
- Pricing (checked 2026-10-17): "Speech to Speech (grok-voice-3.0)" costs $0.08/min ($4.80/hr) plus "$0.004 / text input" (unit unspecified). grok-voice-2.0 is "Deprecated" at the same price. — [xAI models page](https://docs.x.ai/docs/models)
- Independent: Grok Voice 3.0 scores 99% Big Bench Audio (98.5% in the site FAQ) with **0.81 s time-to-first-audio**, the lowest TTFA among the top-ranked models extracted. — [Artificial Analysis](https://artificialanalysis.ai/speech-to-speech)

### Inferences
- The flat per-minute price makes cost predictable and avoids context re-read growth in long sessions, assuming per-minute billing covers context, which the docs do not say.

### Gaps
- No documented custom function-calling schema (only built-in `web_search` was shown), no session limit, no GA/beta label, no voice list, no realtime language list, and no Hungarian confirmation. A dedicated xAI realtime API reference page was not fetched.

## 4. Other hosted STS: Amazon Nova Sonic, Microsoft/Azure

### Takeaway
**Amazon Nova 2 Sonic** (Bedrock) is documented and has strong agentic features (async tools, RAG), but it covers only seven languages (no Hungarian) and has an 8-minute connection limit. **Nova 2.5 Sonic** reportedly went GA on 2026-10-05, but I could not confirm it on an AWS page. **Azure Voice Live** is a managed wrapper rather than a model. It runs OpenAI realtime models natively or wraps text LLMs in Azure STT/TTS, and adds Azure's 140+ STT / 150+ TTS locales, noise suppression, echo cancellation and avatars, with data-zone/regional processing options.

### Cited Findings
**Amazon Nova Sonic**
- Nova 2 Sonic uses a bidirectional streaming API. Languages: English (US, UK, India, Australia), French, Italian, German, Spanish, Portuguese, Hindi. Polyglot voices handle mid-session language switching. Features: intelligent turn-taking, "graceful handling of user interruptions," RAG grounding, function calling, and "asynchronous tool handling… allowing the assistant to continue speaking while tools process." Mixed audio and text input is supported. "Connection limit of 8 minutes, with connection renewal and session continuation pattern available in code samples." — [AWS Nova 2 user guide](https://docs.aws.amazon.com/nova/latest/nova2-userguide/using-conversational-speech.html)
- Nova 2 Sonic pricing is not confirmed on an AWS page. Most secondary sources say about $3.00/1M speech input and $12.00/1M speech output tokens (about $0.015/min), but CallMissed lists $4.00/$15.00, which conflicts. — [techplained](https://www.techplained.com/amazon-nova-2); conflicting [callmissed](https://www.callmissed.com/models/nova-sonic-2)
- Nova 2.5 Sonic (secondary only): GA on Bedrock 2026-10-05 in US East, US West, Stockholm and Tokyo. Claimed better reasoning, instruction following and tool-call accuracy, plus lower latency, with no published benchmarks. Reported 256K context and seven languages. Pricing reportedly matches Nova 2 Sonic, while one aggregator lists $1.00/1M audio input. — [aiweekly](https://aiweekly.co/alerts/amazons-nova-25-sonic-voice-model-hits-bedrock-in-four-regions); [tproger](https://tproger.ru/news/aws-vypustila-nova-2-5-sonic-uluchwila-rassuzhdeniya-i-vyzovy-inst); [llmreference](https://www.llmreference.com/model/nova-2-5-sonic). **Unconfirmed on AWS.**

**Azure Voice Live API** (doc dated 2026-10-08, updated 2026-10-15)
- A fully managed STS API with WebSocket transport, mostly event-compatible with the Azure OpenAI Realtime API. Native STS models: `gpt-realtime-2.1` (global / `-datazone` / `-regional`), `gpt-realtime-2.1-mini`, `gpt-realtime-1.5`, `gpt-realtime`, `gpt-realtime-mini`, `azure-realtime` (with dedicated `azure-realtime-native` voices), and `phi4-mm-realtime` (preview). Cascaded options run Azure STT → LLM (gpt-4o/4.1/5.x, including `gpt-5.6-terra` and `gpt-5.6-luna`) → Azure TTS. Realtime models can optionally output through Azure TTS voices, including custom voice. Features: 140+ STT locales, 600+ voices in 150+ TTS locales, noise suppression, echo cancellation, interruption and end-of-turn detection, avatars, function calling. Pricing is tiered Pro / Standard / Lite by model (rates not on this page; "pricing… takes effect on July 1, 2025"). Custom voice and avatar access is limited. — [Microsoft Learn, Voice Live](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/voice-live)
- Microsoft Foundry describes gpt-realtime-2.1 and 2.1-mini as point upgrades to realtime-2. — [Microsoft Foundry blog](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/a-new-chapter-for-realtime-ai-reasoning-translation-and-real-time-transcription/4517124)

### Inferences
- For Hungarian on Azure, the most dependable route is Voice Live with Azure STT/TTS locales (Hungarian is very likely among the 140+/150+ locales, but I did not check the locale list). That makes it partly cascaded rather than pure native STS.
- `-datazone` and `-regional` variants are the main compliance lever for EU data residency with OpenAI realtime models.

### Gaps
- Azure Voice Live per-tier USD rates were not fetched. Whether Hungarian appears in the Voice Live locale table was not checked. I found no technical description of `azure-realtime`.

## 5. Open full-duplex / self-hostable models

### Takeaway
The open duplex lineage is still **Kyutai Moshi (2024)** plus its derivatives. **NVIDIA PersonaPlex-7B** (2026-01-15) adds persona and voice control on top of Moshi. Kyutai has released RL-tuned "seamless" variants, and **NVIDIA's NemotronLabs VoiceChat** (arXiv, Sep 2026) is the first open duplex model with native tool calling, though tool argument accuracy is still weak. All are effectively **English-only** and need a datacenter-class GPU. None is a drop-in replacement for a hosted agent with tools.

### Cited Findings
- **Kyutai Moshi:** code is MIT (Python, web client) and Apache (Rust backend), and "all models are released under the CC-BY 4.0 license." 7B Temporal Transformer. Latency is 160 ms theoretical (80 ms Mimi frame + 80 ms acoustic delay) and "as low as 200 ms on an L4 GPU" in practice (vendor-reported). PyTorch needs about 24 GB VRAM. MLX (int4/int8/bf16) runs on Apple Silicon (tested on an M3 MacBook Pro), and Rust supports CUDA or Metal. — [kyutai-labs/moshi](https://github.com/kyutai-labs/moshi)
- Kyutai's 2026 releases were Hibiki-Zero (Feb 2026, simultaneous speech translation) and Pocket TTS (Jan 2026, 100M-param CPU TTS). I found no new Kyutai duplex dialogue model in 2026. — [Trae learn page](https://learn.traeai.com/t/ai-engineering/phases/06-speech-and-audio/15-streaming-speech-to-speech-moshi-hibiki); [kyutai.org TTS](https://kyutai.org/tts/)
- Kyutai's RL variants `moshika-rl-seamless` and `personaplex-rl-seamless` use GRPO post-training with axis-specific rewards for pause handling, turn-taking, backchanneling and interruptions (arXiv 2606.11167). — [HF kyutai/moshika-rl-seamless](https://huggingface.co/kyutai/moshika-rl-seamless); [arXiv 2606.11167](https://arxiv.org/html/2606.11167v1)
- **NVIDIA PersonaPlex-7B-v1** (released 2026-01-15): built on Moshi (`kyutai/moshiko-pytorch-bf16`) and governed by the "NVIDIA Open Model License Agreement" (the Moshi base is CC-BY-4.0). The page says 7B in the architecture section but 8B in the file info. **English only**. Supported on Ampere (A100) and Hopper (H100) GPUs under Linux, tested on A100 80 GB. "Ready for commercial use." Access is gated. FullDuplexBench smooth turn-taking latency is 0.170 and interruption latency 0.240 (units not stated; vendor-reported). No tool calling. — [HF nvidia/personaplex-7b-v1](https://huggingface.co/nvidia/personaplex-7b-v1). The paper is arXiv 2602.06053 and was accepted at ICASSP 2026 per secondary sources. — [MarkTechPost](https://www.marktechpost.com/2026/01/17/nvidia-releases-personaplex-7b-v1-a-real-time-speech-to-speech-model-designed-for-natural-and-full-duplex-conversations/)
- A community **PersonaPlex tool-calling fine-tune** keeps listening while an external API call runs. — [HF abhinavpgagi/personaplex-tool-calling](https://huggingface.co/abhinavpgagi/personaplex-tool-calling)
- **NemotronLabs VoiceChat** (arXiv 2609.21967, v1 2026-09-18, v2 2026-10-01): "an open full-duplex speech-to-speech model with native tool-calling capabilities." Architecture: streaming speech encoder, then a decoder-only LM with parallel streams for agent text and function calls, then an auxiliary RNN-T branch for incremental user transcription, then a streaming TTS decoder. Author-reported benchmarks: Full-Duplex-Bench 1.0 has the lowest pause-handling takeover among open-weight systems and 100% takeover after interruptions; FDB 1.5 resumes after backchannels 93% of the time; VoiceBench 55.1; **FDB 3.0 tool-selection F1 82.5%**, with "argument accuracy and end-to-end tool execution" named as needing improvement. The arXiv page does not state weights license, size or languages. — [arXiv 2609.21967](https://arxiv.org/abs/2609.21967)
- Open models are also on the independent leaderboard: StepAudio 3 Realtime (100% Big Bench Audio but 8.83 s TTFA), Step-Audio R1.1 Realtime (98%, 1.53 s), and Qwen Audio 3.0 Realtime Plus / Qwen3.5 Omni Plus Realtime (99%, 1.54 s / 2.64 s; these are listed with API prices, so they may be hosted rather than open). — [Artificial Analysis](https://artificialanalysis.ai/speech-to-speech)

### Inferences
- For a Hungarian-language agent, no open duplex model found here is usable as-is (Moshi and PersonaPlex are English-only, and VoiceChat's languages are unstated). Self-host STS is realistic only for English or with fine-tuning.
- Self-hosting PersonaPlex means one A100/H100-class GPU per small number of concurrent streams. Concurrency per GPU is undocumented.

### Gaps
- **Sesame CSM** was not researched this pass. As far as I know it is a conversational TTS / speech-generation model, not a full-duplex STS agent model, but I did not confirm its license or capabilities.

## 6. Native STS vs cascaded STT→LLM→TTS: when each wins

### Takeaway
Practitioner and vendor consensus in 2026 is that **cascades still dominate production**: they win on tool reliability, model choice, voice choice, auditability, per-language quality guarantees and usually cost. **Native STS wins on latency, prosody/emotion awareness and natural turn-taking**. The converging pattern is a hybrid: duplex voice front end plus text-LLM backend (GPT-Live delegation, Azure Voice Live, Nova async tools). Most comparison sources are vendors selling one side.

### Cited Findings
- Typical numbers from secondary sources: cascaded TTFA about 600–1200 ms vs STS about 300–500 ms. The gap shrinks, but does not disappear, against a well-optimized streaming cascade. Cascades discard prosody at the STT step. Cascades let you swap components and trace faults per stage, while STS exposes only a transcript. Cascades inherit mature LLM function calling, and STS tool calling "works but is newer." One source puts OpenAI Realtime at about 10x a chained pipeline's cost and Nova Sonic near cascade rates. Overall recommendation: cascade for compliance-heavy, tool-heavy or auditable work; STS for latency-sensitive, expressive consumer use. — [FutureAGI](https://futureagi.com/blog/cascaded-voice-ai-vs-speech-to-speech-2026/); [Soniox wiki](https://soniox.com/wiki/speech-to-speech-models-vs-pipelines); [Concret.io](https://www.concret.io/blog/cascade-vs-speech-to-speech-voice-agent-architecture); [Coval](https://www.coval.ai/blog/voice-ai-models-2026/) (all vendor or consultancy blogs; treat numbers as indicative)
- Gradium (sells cascade STT/TTS; co-founders run Kyutai; data as of Sep 2026): "tool use, function calling and structured output are solved problems in the text layer," while for STS, prompt techniques (system prompts, few-shot, RAG) "don't transfer directly." Neil Zeghidour: "the cost to switch the underlying text model is extremely high" in STS. A production cascade typically takes 1.5–3 s end-of-speech to agent audio. The cited Coval STT medians run from 992 ms (Deepgram Nova-3) to 2,080 ms (ElevenLabs Scribe v2), and Gradium TTS shows 155 ms P50 TTFA (vendor-cited). STS lacks "uptime guarantees, and enterprise support." — [Gradium](https://gradium.ai/content/cascaded-voice-agent-vs-speech-to-speech-2026)
- Modulate frames enterprise STS as a "black box" and argues cascade wins for enterprise (title and thesis only; not read in full). — [Modulate ebook](https://www.modulate.ai/ebooks/beat-the-black-box-why-cascade-beats-speech-to-speech-for-enterprise-voice-agents)
- X-Talk (arXiv 2512.18706) argues the modular S2S dialogue system's potential is "underestimated" (title-level claim). — [arXiv 2512.18706](https://arxiv.org/pdf/2512.18706)
- Vendor evidence for the hybrid thesis: OpenAI reports GPT-Live-1 + GPT-6 Astra backend at 83.6% Tau3 vs 45.7% for single-model GPT-Realtime-2.1. — [OpenAI forum](https://community.openai.com/t/introducing-gpt-live-1-in-the-api/1396471)
- Azure markets Voice Live against DIY orchestration on engineering cost and latency, while offering both native and cascaded models under one API. — [Microsoft Learn](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/voice-live)

### Inferences
- **Choose native STS when:** sub-second turn-taking and emotional or prosodic responsiveness drive the product (companions, coaching, consumer assistants); tools are few and simple; the language is well covered; and the vendor's voice catalog is acceptable.
- **Choose cascade when:** you need a specific or brand-cloned voice (realtime models offer a fixed catalog, and OpenAI cannot change voice mid-session), strict tool and argument accuracy, auditable text transcripts as the system of record, a lower-resource language like Hungarian with a best-in-class STT/TTS for that language, or the freedom to swap the LLM.
- **Hybrid:** for tool-heavy agents that still want duplex feel, the 2026 vendor direction (GPT-Live delegation, Gemini NON_BLOCKING async tools, Nova async tools) is a voice layer that keeps talking while a text model runs the tools.

### Gaps
- I found no independent head-to-head benchmark of the same task on STS vs cascade with cost, latency and tool accuracy all measured. Artificial Analysis has a cascaded table (dated July 2026) that was not extracted.

## 7. Known failure modes

### Takeaway
The documented and anecdotal failure modes are: weaker tool and argument accuracy in voice mode than the same-generation text model; audio that diverges from the transcript (the "hallucinated audio" class); transcript bugs; fixed voices per session; hard session and connection caps that force reconnect logic; and cost that grows with context in token-billed sessions. Most reports are forum anecdotes, often on older snapshots.

### Cited Findings
- **Tool reliability:** the forum thread "Realtime Speech-to-Speech: Poor function calling performance vs vanilla gpt4o" exists (body not read; anecdotal, older generation). — [OpenAI forum](https://community.openai.com/t/realtime-speech-to-speech-poor-function-calling-performance-vs-vanilla-gpt4o/975694). Open-model evidence: NemotronLabs VoiceChat reaches 82.5% tool-selection F1 but names argument accuracy and end-to-end execution as weaknesses. — [arXiv 2609.21967](https://arxiv.org/abs/2609.21967). Vendor evidence: GPT-Realtime-2.1 alone scores 45.7% on Tau3 (vendor-reported). — [OpenAI forum](https://community.openai.com/t/introducing-gpt-live-1-in-the-api/1396471)
- **Hallucinated audio / transcript divergence:** "Hallucination from Realtime audio API" reports the model saying an unrelated personal sentence mid-conversation that does not appear in logged transcripts. A related thread reports extra audio not present in the transcription (anecdotal, older snapshots). — [OpenAI forum](https://community.openai.com/t/hallucination-from-realtime-audio-api/1113538)
- **Transcript leakage bug:** a forum bug report (seen as a title only) says the Realtime transcript returned other users' data and internal tokens on `gpt-realtime-2025-08-28`. This is unverified and historical. — listed in [OpenAI forum search results](https://community.openai.com/t/hallucination-from-realtime-audio-api/1113538)
- **GPT-Live transcript gap:** a user reports "GPT-Live doesn't transcribe the user's voice," contrary to OpenAI's claim. Unresolved. — [OpenAI forum](https://community.openai.com/t/introducing-gpt-live-1-in-the-api/1396471)
- **Voice lock and drift:** OpenAI voice is fixed after the first audio in a session. — [OpenAI conversations guide](https://developers.openai.com/api/docs/guides/realtime-conversations). I found no source documenting voice drift over long sessions.
- **Session/connection caps:** OpenAI sessions max 60 min. — [OpenAI](https://developers.openai.com/api/docs/guides/realtime-conversations). Gemini allows 15 min audio-only without compression, connections of about 10 min, and resumption tokens valid for 2 h. — [Google](https://ai.google.dev/gemini-api/docs/live-session). Nova 2 Sonic connections are capped at 8 min. — [AWS](https://docs.aws.amazon.com/nova/latest/nova2-userguide/using-conversational-speech.html)
- **Interruption semantics differ:** Gemini cancels and discards the generation on VAD interruption. — [Google](https://ai.google.dev/gemini-api/docs/live-guide). In GPT-Live, backend work continues after an interrupt unless the app cancels it. — [OpenAI](https://developers.openai.com/api/docs/guides/live). OpenAI's WebSocket path needs client-side `conversation.item.truncate`, or the model's context includes audio the user never heard. — [OpenAI](https://developers.openai.com/api/docs/guides/realtime-conversations)
- **Reasoning cost/latency:** OpenAI says higher reasoning effort "can raise latency and output token usage." — [OpenAI](https://developers.openai.com/api/docs/models/gpt-realtime-2.1). Gemini bills thinking at output rates. — [Google pricing](https://ai.google.dev/gemini-api/docs/pricing)
- **Generic function-calling mitigations** from older text-model threads: validate arguments, return an "unknown function" error for hallucinated tool names, and append a "tool already ran successfully" result to prevent repeat calls. — [OpenAI forum](https://community.openai.com/t/how-to-stop-model-from-hallucinating-function-names/591674); [OpenAI forum](https://community.openai.com/t/gpt-function-calling-hallucinations-runs-3-times/315196)

### Inferences
- **Cost blowups:** in token-billed STS (OpenAI Realtime, Gemini per-token), each response re-reads the accumulated conversation as input. Cost per turn therefore grows with session length, which is why cached-audio pricing ($0.40/1M on gpt-realtime-2.1 vs $32 uncached) and Gemini context compression matter. Per-minute billing (GPT-Live $0.05/min voice layer, Grok $0.08/min, Gemini's per-minute option) bounds this. This follows from the billing model; I found no vendor statement or post-mortem documenting a specific blowup.
- On WebSocket transports, a missing truncate on barge-in is a likely source of "the model thinks it said something the user never heard" confusion.

### Gaps
- No systematic or independent measurement of hallucinated audio rate, voice drift or tool-call accuracy for current (2026) hosted models was found. Reddit (r/LocalLLaMA, r/voiceAI) and Hacker News practitioner threads were not reached within the budget.
